## Context

Vehicle emission testing centers and fleet workshops needed a centralized web system to monitor **AG-420 ADI** hardware analyzer readings across multiple branches without manually copying logs over serial ports or USB drives.

## Problem

1. **Intermittent workshop connectivity**: Brief cellular drop-offs during an active vehicle test must not corrupt or drop certified readings.
2. **Strict multi-tenant boundaries**: Multiple partner workshops share one web deployment; telemetry streams and calibration certificates must never leak across tenants.
3. **Instant operator legibility**: Technicians need clear live readouts for CO, HC, CO2, O2, and pass/fail thresholds directly in the browser.

## Approach & Technical Trade-Offs

- **MQTT QoS 1 over Short-Interval HTTP Polling**: Topic structure `bench/{tenant_id}/{device_id}/telemetry` keeps payloads compact and supports reliable queuing during transient disconnects. *Trade-off*: requires a persistent PHP subscriber worker, which is offset by significantly lower bandwidth overhead.
- **Shared Database with Indexed `tenant_id` Scope**: Rather than maintaining separate schemas per workshop, centralized repository guards enforce `tenant_id` scoping across every query.

## Architecture

Field units publish sensor frames to the MQTT broker, where the PHP worker validates calibration ranges, persists audit records to MySQL, and pushes live telemetry updates to the browser console.

## Outcomes

- Device provisioning, real-time gas analyzer monitoring, and test history auditing unified into a single multi-tenant platform.
- Quantitative production metrics remain withheld until client verification concludes.

## Lessons Learned

Hardware-connected web software requires designing failure states first: malformed payload rejection, device offline heartbeats, and broker ACLs matter as much as UI charts.
