## Context

Last-mile delivery couriers frequently move between stable urban 4G coverage and residential dead zones where network requests silently time out at the exact moment a parcel changes hands.

## Problem

1. **Blocked status transitions offline**: Blocking courier checkmarks on network roundtrips stalls field operations.
2. **Cognitive overload on small screens**: Drivers need manifest lists, recipient stops, and proof-of-delivery triggers in minimal taps.
3. **Maintainable state boundaries**: Logistics rules change fast and require decoupled UI/data layers.

## Approach & Technical Trade-Offs

- **Local Outbox Pattern with Room + MVVM**: Writing every delivery confirmation locally first allows instant UI progression and deterministic background retry. *Trade-off*: requires explicit sync-state indicators so couriers see queued vs confirmed statuses clearly.
- **Native Kotlin over Cross-Platform Wrappers**: Tighter control over Android foreground location lifecycles, camera permissions, and leaner APK sizing.

## Architecture

Screens subscribe strictly to `ViewModel` state streams backed by a `Repository` orchestrating local `Room` persistence and remote REST synchronization.

## Outcomes

- Modular Kotlin MVVM logistics codebase ready for field expansion.
- Operational fleet telemetry metrics remain unverified prior to full dispatch rollout.

## Lessons Learned

Reliability in field logistics means treating network loss as the default state rather than an exceptional edge case.
