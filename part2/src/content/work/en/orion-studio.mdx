## Context

3D showcase websites routinely sacrifice Largest Contentful Paint (LCP) and overheat mid-tier phones. **ORION Studio** explored pairing scroll-linked 3D depth with strict performance and accessibility boundaries.

## Problem

1. **Render-blocking WebGL bundles** delay first-contentful typography on slower networks.
2. **Motion accessibility**: Users enabling `prefers-reduced-motion` must still read the complete narrative effortlessly.
3. **DOM-to-camera harmony**: Motion should direct eye flow rather than obscure primary calls to action.

## Approach & Technical Trade-Offs

- **SSR-First Narrative + Lazy Dynamic Scene**: Copy and CTAs ship as plain server HTML before asynchronously booting the interactive canvas. *Trade-off*: brief subtle background fade-in on slow 3G/4G, traded intentionally for instant text readability.
- **Capability Guard**: Automatically skips heavy 3D initialization when reduced motion is active or viewport constraints dictate.

## Architecture

Next.js outputs semantic HTML first, allowing a tiny client guard to decide between binding scroll progress to the 3D viewport or resting on an accessible static layout.

## Outcomes

- Clean separation between readable content and optional spatial enhancement.
- Cross-device telemetry figures remain withheld for verification.

## Lessons Learned

Sophisticated web motion is defined by restraint, predictable pacing, and respect for hardware limits.
