## Context

Guided prayer-learning apps must give instant posture feedback privately without requiring fast continuous internet connections or streaming bedroom camera feeds to cloud GPUs.

## Problem

1. **Privacy and latency constraints**: Cloud inference introduces roundtrip lag and sensitive video uploads.
2. **Python-to-Kotlin tensor alignment**: Raw YOLO output matrices require careful coordinate rescaling, rotation handling, and Non-Maximum Suppression inside Kotlin.
3. **APK size vs accuracy**: Full desktop weights exceed practical mobile storage budgets without quantization.

## Approach & Technical Trade-Offs

- **On-Device TFLite Execution over Cloud Inference**: Running the 7-class model directly on Android preserves user privacy and cuts per-user inference cost to zero. *Trade-off*: demands explicit Kotlin NMS post-processing and strict tensor stride verification.
- **Quantized Export with Delegate Fallback**: Configured hardware delegates (NNAPI/GPU) with graceful CPU fallback across varied Android devices.

## Architecture

A 7-class Python YOLO11 model exports to `.tflite`, ships inside Android assets, and consumes normalized CameraX `ImageAnalysis` buffers in real time.

## Outcomes

- Functional offline 7-class posture inference pipeline running natively inside Kotlin.
- Final latency and size numbers remain withheld for verification pending broad handset profiling.

## Lessons Learned

Verifying RGB normalization, stride alignment, and sensor rotation between Python training and Kotlin camera buffers on day one saves days of subtle coordinate debugging.
