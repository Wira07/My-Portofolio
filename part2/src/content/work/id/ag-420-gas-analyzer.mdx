## Konteks

Bengkel uji emisi kendaraan dan pengelola armada membutuhkan cara terpusat untuk memantau pembacaan alat gas analyzer **AG-420 ADI** dari banyak lokasi cabang tanpa harus memindahkan file log secara manual lewat kabel serial atau USB.

## Masalah

1. **Konektivitas bengkel tidak selalu stabil** — koneksi terputus di tengah sesi pengujian kendaraan tidak boleh menggagalkan pencatatan hasil ukur yang sah.
2. **Isolasi antar-tenant wajib ketat** — satu platform web melayani banyak mitra bengkel dengan perangkat masing-masing; data hasil uji dan riwayat kalibrasi tidak boleh bocor lintas tenant.
3. **Keterbacaan operator lapangan** — teknisi butuh umpan balik angka CO, HC, CO2, O2, serta status ambang batas lulus uji secara seketika di layar browser.

## Pendekatan & Keputusan Teknis (Trade-Off)

- **Protokol MQTT dibanding HTTP Polling dari Perangkat**: Memilih MQTT QoS 1 dengan struktur topik `bench/{tenant_id}/{device_id}/telemetry` membuat payload tetap ringkas dan mendukung antrean pesan saat koneksi seluler bengkel sempat putus. *Trade-off*: membutuhkan proses worker PHP persisten untuk subscribe topik, namun jauh lebih hemat bandwidth dibanding REST polling interval pendek.
- **Shared Database, Isolated `tenant_id` Indexing**: Dibanding memelihara ratusan schema MySQL terpisah, seluruh data tersimpan dalam tabel terpartisi logis oleh `tenant_id` dan `device_id` dengan middleware otorisasi terpusat di PHP. *Trade-off*: membutuhkan disiplin tinggi pada setiap query repository agar tidak pernah melewatkan scope tenant.
- **Buffer Status Terakhir vs Riwayat Penuh**: Pembacaan live dipisahkan dari arsip sertifikat uji resmi sehingga dashboard operator tetap ringan meski log historis terus tumbuh.

## Arsitektur

Struktur sistem menghubungkan perangkat sensor di jalur uji langsung ke broker MQTT, diproses oleh service ingestor untuk validasi rentang sensor, disimpan ke MySQL untuk audit, dan diproyeksikan ke antarmuka web operator.

## Hasil

- Portal manajemen perangkat, pemantauan pembacaan gas real-time, dan pencatatan riwayat pengujian berhasil disatukan dalam satu arsitektur web multi-tenant.
- Parameter kuantitatif skala produksi (`Latensi Ingestion`, `Jumlah Tenant`, `Retensi`) saat ini ditandai untuk verifikasi bersama pemilik sistem sebelum dipublikasikan secara terbuka.

## Pelajaran

Menangani perangkat keras lapangan berarti merancang asumsi kegagalan sejak awal: validasi format payload rusak, *heartbeat* perangkat offline, dan pembatasan otorisasi topik broker sama pentingnya dengan tampilan antarmuka dashboard itu sendiri.
